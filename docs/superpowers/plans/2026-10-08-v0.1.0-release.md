# v0.1.0 Release Implementation Plan

Date: 2026-10-08

## Goal

Create a truthful, reproducible first release of E-commerce Lead Automation
without changing its business workflow or widening its data-risk surface.

## Plan

1. **Version identity, red phase**
   - Extend `tests/test_version.py` with expectations for `APP_VERSION` and a
     combined version/build label.
   - Run only that file and confirm failure is caused by the missing API.
2. **Version identity, green phase**
   - Add the minimum implementation to `services/version.py`.
   - Update the existing footer in `app.py` to consume the pure label.
   - Run the version tests, then the full test suite.
3. **Maintenance configuration**
   - Change the pytest constraint to `pytest>=9.0.3,<10`.
   - Update pytest references in both READMEs and third-party notices.
   - Upgrade `actions/checkout` and `actions/setup-python` to Node 24-compatible
     major releases.
   - Add weekly pip and GitHub Actions Dependabot checks.
4. **Public evidence**
   - Add CI and Release badges to the English README.
   - Add a short Engineering evidence section using only reproducible facts.
5. **Local release gate**
   - Install the declared development requirements in an isolated environment.
   - Run tests, compileall, pip check, YAML validation, diff checks, and a
     tracked-file secret-pattern scan.
6. **Pull request and hosted verification**
   - Push the release branch, open a pull request, and wait for every required
     check to complete.
   - Review the final diff and merge without rewriting public history.
7. **Publish**
   - Verify `main` locally and remotely.
   - Create and push an annotated `v0.1.0` tag.
   - Publish release notes with fixed tag and final-run links.
   - Enable Dependabot security updates and verify the repository's security
     controls and open-alert counts.
8. **Post-release audit**
   - Re-download public release metadata anonymously where possible.
   - Verify branch, tag, release target, and CI SHAs agree.
   - Record the remaining manual GitHub profile and X identity tasks separately.
