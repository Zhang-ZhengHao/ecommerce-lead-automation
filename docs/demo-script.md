# 客户演示脚本（约 5 分钟）

## 目标

让客户看到“留言表 → 可审核线索 → 可下载结果”的完整闭环，不把规则演示误说成模型准确率承诺。

先按[本地运行说明](../README.zh-CN.md#本地运行)启动应用，在新的浏览器标签页开始本次演示。全程使用内置合成数据，无需 API key。

## 流程

1. 点击“载入示例数据”，查看 4 条留言。说明 `demo-contact-001` 等是合成标识。
2. 在“行业预设”选择“电商咨询”，点击“保存回复设置”；说明预设只是客户校准起点。
3. 选择“演示规则”，点击“开始处理”。这组示例应得到 2 条高意向、1 条中意向、1 条低意向，回复状态均为“待确认”。
4. 在“选择要编辑的行”中选择第一条采购留言，点击“采用 AI 草稿并编辑”。查看“最终回复”已有草稿，但该行回复状态仍为“待确认”。
5. 在“线索阶段（仅当前会话）”选择“已联系”，将“最终回复”改为“您好，请补充您需要的规格或型号，方便继续沟通。”，点击“保存并确认”。核对该行的回复状态为“已确认”，其余 3 行仍为“待确认”。
6. 点击“下载全部结果（草稿）”和“下载可发送结果”。前者的“全部结果”表应有 4 条数据，后者的“可发送”表只含刚确认的 1 条；核对其阶段为“已联系”，最终回复为刚输入的文字，并查看导出用途和原始行号。

这组示例没有待复核行，页面不会显示“下载待复核行”按钮。演示结束时说明：线索阶段只在当前会话保存；应用不会自动登录店铺、自动发送或保存历史，真实 AI 仍需客户确认数据合规和费用。

## 可报价模块

- 模板字段映射与客户标签校准；
- 行业预设、禁词和回复语气配置；
- Excel/CSV 导入、漏斗字段和人工复核导出；
- 受控环境下的 OpenAI 兼容 API 接入（费用、数据留存另行确认）。
